# HW06 – Report

## 1. Dataset

- Какой датасет выбран: `S06-hw-dataset-02.csv`
- Размер: (18000, 39)
- Целевая переменная: `target` (бинарная классификация)
  - Класс 0: 73.7% (13273 объекта)
  - Класс 1: 26.3% (4727 объектов)
  - Датасет имеет умеренный дисбаланс классов
- Признаки: 
  - 37 числовых признаков типа `float64`
  - Признаки f01-f35: числовые признаки
  - Признаки x_int_1, x_int_2: числовые признаки (возможно, содержат нелинейные взаимодействия)
  - Категориальных признаков нет
  - Пропущенных значений нет

## 2. Protocol

- Разбиение: train/test (80/20), `random_state=42`, `stratify=y`
  - Размер обучающей выборки: 14400 объектов
  - Размер тестовой выборки: 3600 объектов
  - Стратификация обеспечивает сохранение пропорций классов в обеих выборках
  
- Подбор: CV на train
  - Использован `StratifiedKFold` с 5 фолдами (`n_splits=5`)
  - `shuffle=True`, `random_state=42` для воспроизводимости
  - Оптимизировали метрику **ROC-AUC** через `GridSearchCV`
  - Подбор гиперпараметров выполнялся только на train, test использовался один раз для финальной оценки

- Метрики: accuracy, F1, ROC-AUC
  - **Accuracy**: общая доля правильных предсказаний, подходит для оценки общего качества
  - **F1-score**: гармоническое среднее precision и recall, важно для несбалансированных датасетов (учитывает оба класса)
  - **ROC-AUC**: площадь под ROC-кривой, показывает способность модели различать классы независимо от порога классификации
  - Эти метрики уместны, так как:
    - Датасет имеет дисбаланс классов (73.7% vs 26.3%)
    - ROC-AUC позволяет оценить качество вероятностных предсказаний
    - F1-score учитывает качество предсказаний для минорного класса

## 6. Conclusion

1. **Деревья решений и контроль сложности**: Контроль сложности дерева через `max_depth` и `min_samples_leaf` критически важен для предотвращения переобучения. DecisionTree показал ROC-AUC 0.8374, что значительно лучше baseline, но хуже ансамблей.

2. **Ансамбли превосходят одиночные модели**: RandomForest (ROC-AUC: 0.9275) и GradientBoosting (ROC-AUC: 0.9304) значительно превосходят одиночное дерево, демонстрируя эффективность ансамблевых методов для задач с нелинейными зависимостями.

3. **Boosting vs Bagging**: GradientBoosting показал немного лучший результат, чем RandomForest, что может быть связано с последовательным улучшением модели и лучшей адаптацией к нелинейным взаимодействиям в данных.

4. **Честный ML-протокол**: Разделение на train/test с фиксированным `random_state`, подбор гиперпараметров только на train через CV, и однократное использование test для финальной оценки - это основа воспроизводимого и честного эксперимента.

5. **Стратификация важна**: Использование `stratify=y` при разбиении данных обеспечило сохранение пропорций классов, что критично для корректной оценки метрик на несбалансированных датасетах.

6. **Permutation Importance для интерпретации**: Permutation importance позволяет понять, какие признаки действительно важны для модели, что полезно для feature selection и понимания бизнес-логики задачи.
